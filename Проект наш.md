# Проект «Гигантская тыква»: Требования и Задачи

## Функциональные требования (ФТ)

1. **Поиск и ввод данных:**
   - Система должна принимать на вход данные о двух тыквах (поиск по названию формата «XXX Фамилия YYYY» или по весу) с функцией автодополнения при вводе.
   - Пользователь может задать целевой порог веса (например, > 1000 кг).
2. **Калькулятор скрещивания (Прогноз):**
   - Система должна рассчитывать вероятность (в %) того, что потомство от выбранной пары превысит заданный порог.
   - Система должна отображать доверительный интервал (погрешность) и количество наблюдений (на основе скольких потомков сделан прогноз).
3. **Подбор партнера:**
   - Система должна предлагать ТОП-N лучших партнеров для выбранной тыквы с указанием вероятности успеха и статистики по каждому кандидату.
4. **Рейтинг и визуализация:**
   - Система должна строить интерактивное дерево родословной (до 5+ поколений).
   - Система должна формировать рейтинг семян и линий на основе исторических данных.
5. **Объяснимость :**
   - Система должна показывать, на каких именно данных/тыквах основан прогноз (факторный анализ: вес предков, % от OTT, навык выращивателя).
6. **Экспорт данных:**
   - Возможность выгрузить отчет о прогнозе или родословной в форматах PDF или CSV.

## Нефункциональные требования (НФТ)

1. **Производительность:** Время расчета прогноза для одной пары не должно превышать 1-2 секунд (согласно критерию заказчика — до 1 минуты на всю оценку).
2. **Надежность и масштабируемость данных:** База данных должна выдерживать хранение и обработку 50 000+ записей без потери скорости работы.
3. **Достоверность:** Алгоритмы парсинга и очистки должны обеспечивать распознавание имен формата «XXX Фамилия YYYY» не менее чем в 90% случаев.
4. **Юзабилити (Удобство):** Интерфейс должен быть интуитивно понятным для агронома (без сложных технических терминов), вес отображаться как в кг, так и в фунтах.
5. **Обновляемость:** Архитектура должна позволять легко загружать новые данные после каждого сезона (ETL-процессы) без необходимости переписывать код.
6. **Безопасность:** Защита API от несанкционированного доступа (базовая авторизация) и валидация вводимых данных (защита от отрицательных весов и SQL-инъекций).

## Бэклог задач для реализации

### Артем 
- Написать парсер  для сбора данных с `pumpkinfanatic.com` (родословные, вес, ОТТ, год, родители).
- Написать парсер для `bigpumpkins.com` (результаты взвешиваний по годам).
- Реализовать функцию парсинга строки "XXX Фамилия YYYY" для нормализации данных (извлечение веса, фамилии, года).
- Провести EDA (разведочный анализ данных): посчитать распределение весов, найти выбросы, оценить процент заполненности полей (особенно потомков).
- Сформировать датасет для обучения: сгруппировать данные по линиям (мать/отец), создать целевую переменную (вес потомка).(это, если все-таки с мл будем работать)
- Написать бейзлайн-модель прогнозирования для предсказания веса или вероятности превышения порога.(это, если все-таки с мл будем работать)
- Реализовать расчет поправок (навык выращивателя, год) для корректировки прогноза.

###  Мирон 
- Развернуть локальную базу данных.
- Спроектировать и создать схему БД: таблицы `pumpkins` (id, вес, год, ОТТ, цвет), `growers` (фамилия, страна), `pedigree` (id_тыквы, id_матери, id_отца), `progeny` (связь семян и потомков).
- Настроить ETL-процесс (скрипт на Python), который берет JSON/CSV от парсера Артема и заливает в БД (с обработкой дублей).
- Реализовать алгоритм построения графа родословной (например, через библиотеку `networkx` или рекурсивные SQL-запросы) для вывода дерева до N-го поколения.
- Написать SQL-запросы/функции для агрегации статистики по потомкам (сколько детей, средний вес детей, максимальный вес).
- Поднять FastAPI приложение.
- Написать эндпоинт `GET /search?q=` для автодополнения при вводе названия тыквы.
- Написать эндпоинт `POST /predict` — принимает ID двух тыкв и порог, возвращает вероятность и интервал.
- Написать эндпоинт `GET /recommend/{id}` — возвращает список лучших партнеров для выбранной тыквы.
- Написать эндпоинт `GET /tree/{id}` — отдает JSON с графом родословной для фронтенда.

### Егор 
- Инициализировать проект , настроить роутинг.
- Сверстать макет главной страницы (дашборда) согласно прототипу.
- Реализовать UI-компонент "Калькулятор скрещивания": инпуты с автодополнением (подтягивать названия из БД), ползунок/инпут для порога веса.
- Реализовать UI-компонент "Подбор партнера": таблица с сортировкой по вероятности, подсветка топ-результатов.
- Реализовать компонент визуализации дерева родословной (например, через библиотеку `react-d3-tree` или аналоги).
- Настроить интеграцию с API: отправка запросов на бэкенд, обработка загрузки и вывод ошибок.
- Реализовать кнопку и логику выгрузки отчета в PDF/CSV на клиенте (или скачивание с бэкенда).

### Настя
- Создать тестовую базу (набор из 10-20 тыкв с известными родословными) для проверки работы калькулятора.
- Проверить парсер: залить данные, убедиться, что нет "битых" имен и отрицательных весов.
- Проверить API: корректно ли возвращаются ошибки (например, если ввести несуществующую тыкву).
- Провести UX-тестирование интерфейса: попробовать самому рассчитать пару на тестовом стенде.
